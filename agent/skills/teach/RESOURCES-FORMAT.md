# RESOURCES.md format

Every teaching workspace must contain a `RESOURCES.md` file listing high-quality, high-trust resources that ground teaching in verified knowledge.

## Template

```markdown
# Resources

## Primary
<!-- Core resources that define the curriculum. Read/used in order. -->

| # | Title | Type | Author/Creator | URL | Credibility | Notes |
|---|-------|------|----------------|-----|-------------|-------|
| 1 | <title> | book / paper / course / docs / repo / video-series | <name> | <URL> | high / medium / needs-verification | <why this resource, what it covers> |

## Supplementary
<!-- Additional resources for depth, alternate perspectives, or specific sub-topics. -->

| # | Title | Type | Author/Creator | URL | Credibility | Notes |
|---|-------|------|----------------|-----|-------------|-------|

## Communities
<!-- Places where practitioners gather. See GLOSSARY.md for community preference. -->

| Name | URL | Platform | Activity | Beginner-Friendly | Notes |
|------|-----|----------|----------|-------------------|-------|
| <name> | <URL> | subreddit / discord / discourse / meetup / etc. | high / medium / low | yes / somewhat / no | <entry point recommendation> |
```

## Rules

- Resources must be verifiable — no broken links, no vague references
- Credibility is based on: author reputation, peer review, institutional backing, community consensus, and cross-referencing
- Primary resources are the core curriculum; supplementary resources fill gaps
- Before the table is well-populated (fewer than 3 primary resources), your priority is finding more
- Update when better resources are discovered; move deprecated ones to a `## Deprecated` section with a reason
- Communities should include an entry point recommendation (e.g., "lurk first, then ask in the weekly questions thread")
